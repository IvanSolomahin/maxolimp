# Каталог олимпиад

Одна запись в `subject_olympiad` — одна связка названия олимпиады и предмета. Её `id` используется в рекомендациях, карточке и избранном. Льготы и этапы в исходной таблице Excel привязаны только к названию олимпиады, поэтому хранятся на уровне `olympiad` и доступны для всех её предметов.

Выдача рекомендаций группирует связи по олимпиаде: одна олимпиада показывается одной карточкой независимо от числа связанных предметов. `id` карточки соответствует первой связи этой олимпиады и остаётся пригодным для запросов этапов.

`sql/seed.sql` содержит полную выгрузку из `olympiads_benefits.xlsx`. Для обновления выгрузки:

```bash
python3 olymp_find_service/import_workbook.py INPUT.xlsx olymp_find_service/sql/seed.sql
```

Скрипт проверяет структуру и ссылки между листами. `seed.sql` заменяет содержимое каталога в транзакции и приводит обязательность полей к текущей модели. На новой базе Docker Compose выполняет `init.sql`, затем `seed.sql`. Для базы со старой схемой выполните `migrate_subject_identity.sql` и `seed.sql` в одном сеансе `psql`: первая команда открывает транзакцию, вторая завершает её. Миграция удаляет старое избранное вместе со старым каталогом.

Если нужно сохранить существующий каталог, а таблица `favorite` пуста, выполните `sql/migrate_subject_olympiad_id_preserve_data.sql`. Она добавляет идентификаторы связкам предметов и олимпиад и обновляет внешний ключ избранного без удаления записей. Для каталога, загруженного до добавления подтверждённых предметов, выполните `sql/add_confirmed_subject_links.sql`: скрипт добавит только отсутствующие связи.

В книге у 65 олимпиад отсутствовала связь с предметом. Для 15 из них предметы прямо указаны в поле описания; импортёр добавляет эти 25 связок. Ещё 50 записей остаются без предмета: в исходнике нет достаточно точных данных, чтобы привязать их без догадок.
