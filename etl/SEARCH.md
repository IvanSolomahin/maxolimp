# Векторный поиск по олимпиадным задачам

Поисковый слой находится в [`task_search.py`](task_search.py). Он читает исходные задачи из `olimpiads_data_v2/olimpiads.sqlite3` и хранит собственный SQLite-индекс отдельно. По умолчанию используется `qwen/qwen3-embedding-4b` через [OpenRouter Embeddings API](https://openrouter.ai/docs/api/api-reference/embeddings/create-embeddings). Запрос можно искать по теме задачи, по способу решения или сразу по обоим полям; векторная выдача совмещается с SQLite FTS5.

## Что отправляется на векторизацию

Для каждой задачи создаётся максимум два входных текста и, соответственно, два вектора:

| Вид | Подготовка текста | Для чего нужен |
| --- | --- | --- |
| `topic` | `classifier.strip()`, затем перевод строки и `statement.strip()`; пустые части опускаются | Поиск по условию и теме |
| `solution` | `solution.strip()` целиком | Поиск по способу решения |

Текст ответа (`answer`) в векторы не входит. Решения не разбиваются на чанки. Если поле пустое, вектор для него не создаётся; задача с непустым другим полем остаётся в индексе. Исходная база открывается только для чтения.

Перед отправкой длина каждого текста проверяется [токенизатором Qwen3-Embedding-4B](https://huggingface.co/Qwen/Qwen3-Embedding-4B/blob/main/tokenizer.json). Лимит по умолчанию — 32 768 токенов на **один текст**. Текст не обрезается: слишком длинное решение записывается в таблицу `skipped`, а сама задача остаётся доступна через `topic` и FTS5. Токенизатор загружается один раз в `olimpiads_data_v2/search_indexes/qwen3-embedding-4b-tokenizer.json`.

Непустые тексты отправляются пакетами в `POST /api/v1/embeddings` как массив `input`. По умолчанию пакет содержит до 32 текстов. Ответ проверяется: число векторов и их индексы должны соответствовать запросу, каждый вектор должен содержать 2 560 конечных чисел. Затем числа сохраняются как little-endian `float32`: один вектор занимает 10 240 байт. Код не задаёт `input_type` и использует одну и ту же модель для документов и запросов.

## Где лежит индекс

| Файл | Назначение |
| --- | --- |
| `olimpiads_data_v2/olimpiads.sqlite3` | Исходные задачи, не изменяются поисковым кодом |
| `olimpiads_data_v2/search_indexes/qwen-qwen3-embedding-4b-16a63a113997-2560.sqlite3` | Векторы, тексты, метаданные и FTS5 для модели Qwen и размерности 2 560 |
| `olimpiads_data_v2/search_indexes/qwen3-embedding-4b-tokenizer.json` | Локальный токенизатор модели |
| `olimpiads_data_v2/openrouter.key` | Необязательный локальный файл ключа OpenRouter |

Всё внутри `olimpiads_data_v2/` исключено из Git, включая исходную базу, индекс и ключ. Индекс нужно переносить или резервировать отдельно от репозитория. Для согласованной копии работающей SQLite-базы используйте SQLite Backup API; не копируйте только основной `.sqlite3`-файл во время записи.

Файл индекса выбирается по **ID модели и размерности**; ID входит в читаемую часть имени и в SHA-256-суффикс. Смена модели или размерности создаёт другой файл и требует первого построения её индекса. Возврат к прежней модели использует сохранённые векторы. Для другой модели задайте `--model`, `--dimensions`, `--max-tokens` и её токенизатор через `--tokenizer` или `--tokenizer-url`.

Внутри индекса находятся:

- `documents` — одна строка на `(subject, problem_id)`: тексты, класс, год, URL и SHA-256 подготовленных текстов;
- `document_fts` — FTS5 с полями `topic` и `solution`, связана с `documents` через `rowid`;
- `vectors` — пары `(subject, problem_id, kind)`, хеш текста и бинарный `float32`-вектор;
- `skipped` — тексты, не прошедшие проверку длины, с числом токенов и причиной.

## Повторный запуск и обновления

Основной запуск:

```bash
python3 -m pip install -r requirements.txt
./run_search_index.sh
```

Скрипт читает ключ из `olimpiads_data_v2/openrouter.key`, использует 8 воркеров и пакеты по 32 текста. В терминале отображаются число просмотренных задач, процент, новые векторы, токены, активные запросы, повторы и примерное оставшееся время. Прерванный запуск можно повторить: индексация по хешам пропускает неизменённые векторы и восстанавливает отсутствующие. Изменение условия или классификатора пересчитывает `topic`; изменение решения пересчитывает `solution`. Изменение только метаданных обновляет строку документа без повторной векторизации. Полный запуск без `--limit` и `--subject` также удаляет из индекса задачи, исчезнувшие из исходной базы.

`--workers` задаёт верхнюю границу одновременных запросов. Код начинает максимум с восьми, постепенно увеличивает параллельность после успешных ответов и снижает её при временных сетевых ошибках. Сетевые разрывы и ответы 429/5xx повторяются с паузой до восьми попыток. Размер пакета можно изменить, например `./run_search_index.sh --batch-size 16`. Не запускайте два процесса индексирования для одного и того же файла одновременно: SQLite допускает одного писателя.

Ключ можно также передать через переменную окружения `OPENROUTER_API_KEY`. Файл с ключом держите вне Git; для локального файла подойдёт `chmod 600 olimpiads_data_v2/openrouter.key`.

## Как работает поиск

```python
from task_search import Config, search

results = search(
    "закон сохранения импульса",
    mode="topic",              # topic, solution или both
    method="hybrid",           # fts, vector или hybrid
    subject="physics",         # math или physics
    grade="9", year="2016", k=5,
    config=Config(),
)
```

Для `vector` и `hybrid` нужен ключ OpenRouter; `fts` после построения индекса работает без сети и ключа. В CLI общие параметры ставятся **перед** командой:

```bash
.venv/bin/python task_search.py --api-key-file olimpiads_data_v2/openrouter.key search \
  'закон сохранения импульса' --mode topic --method hybrid --subject physics -k 5
```

FTS5 разбивает запрос на слова и ранжирует совпадения через `bm25`. Векторный поиск создаёт вектор запроса той же моделью и считает косинусное сходство с сохранёнными векторами. Для режима `both` оцениваются оба вида векторов. Метод `hybrid` совмещает ранги FTS5 и векторов по формуле `1 / (60 + rank)` для каждого списка. Поиск возвращает `k` задач; фильтры по предмету, классу и году применяются до ранжирования. Диапазон класса вроде `8-9` подходит для фильтра `--grade 8` и `--grade 9`.

Точные повторы *непустого* условия внутри одного предмета объединяются: первая задача остаётся в результате, остальные ID перечислены в `duplicates` с учётом фильтров. Это сравнение текста после `strip()`, а не смысловое объединение. Длинное решение без вектора по-прежнему ищется через FTS5, а задача — по вектору условия.

Векторный поиск сейчас перебирает подходящие записи SQLite и не использует ANN-индекс. Поэтому задержка растёт с числом векторов и зависит от фильтров, диска и OpenRouter. На одном полном запросе по физике наблюдалось 0,37 с для `fts` и 7,4 с для `hybrid` с сетевым запросом; это пример, а не гарантия времени ответа.

## Проверки качества и скорости

`search_labels.json` содержит стартовые размеченные запросы по обоим предметам и обоим поисковым режимам. `evaluate_search.py` сравнивает `fts`, `vector` и `hybrid` по Recall@k и MRR@k:

```bash
.venv/bin/python evaluate_search.py search_labels.json \
  --api-key-file olimpiads_data_v2/openrouter.key -k 10
```

Восемь стартовых запросов дают только базовую проверку; для вывода о качестве на всей коллекции нужен более широкий набор разметки. Пакеты 8, 16, 32, 64 и 128 сравнивались на одинаковых 256 текстах при восьми воркерах и двух проходах. Пакет 32 дал наибольшую среднюю скорость в этой пробе. Повторить измерение можно командой `.venv/bin/python benchmark_batch_sizes.py`, когда основной индекс не работает. По локальному токенизатору все 39 235 непустых входных текстов содержали около 19,66 млн токенов; стоимость зависит от действующей цены OpenRouter и фактического `usage` в ответах API.

| 8 | 30,94 / 30,57 с | 8,32 |
| 16 | 11,77 / 14,35 с | 19,80 |
| **32** | **7,02 / 14,96 с** | **26,80** |
