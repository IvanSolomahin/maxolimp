# ETL олимпиадных задач

ETL — это три шага: собрать задачи, подготовить поиск и добавить оценки
сложности. На каждом шаге данные сохраняются в одну SQLite-базу.

## Как данные появились

1. **Сбор — `scrape/`.** Парсер обошёл страницы задач по ID на сайтах СДАМ ГИА:
   математика — ID 1–12691, физика — 1–8035. Получили 19 653 задачи:
   11 929 по математике и 7 724 по физике. Ещё 1 073 недоступных ID записаны
   отдельно.
2. **Поиск — `search/`.** Сначала поисковый индекс хранился отдельно. Затем его
   перенесли к задачам в общую базу. Для поиска добавили обычный поиск по словам
   и числовые представления текстов от Qwen3, которые помогают находить похожие
   по смыслу задачи. Получилось 39 235 представлений для условия и решения.
3. **Оценка сложности — `labeling/`.** На пилоте Jev оценил 300 случайных задач;
   20 из них проверили повторно. После пилота размечены все 19 640 задач с
   непустым условием. Ещё 13 задач остались без оценки: их условия пусты.

Скрипты можно запускать снова: сбор пропускает уже сохранённые ID, поиск
обновляет только изменившиеся тексты, а разметка берёт строки без оценки.
Точная копия исходного снимка с нуля не гарантируется: сайт и внешние модели
могут меняться.

## Папки

| Путь | Что в нём |
| --- | --- |
| `scrape/` | Загрузка задач с сайта и сохранение в SQLite. |
| `search/` | Поиск, построение индекса, его замер и проверка качества. |
| `labeling/` | Шкала, пилот и разметка сложности через Jev. |
| `tests/` | Автоматические проверки поиска и разметки. |
| `olimpiads_data_v2/` | Локальная база, ключи, кэш и резервные копии; Git их не хранит. |

Подробности конкретного шага находятся в `search/README.md` и
`labeling/README.md`.

## Итоговая база

Рабочий файл — `olimpiads_data_v2/olimpiads.sqlite3`.

| Таблица | Содержимое |
| --- | --- |
| `problems` | Задачи. Ключ — пара «предмет + ID». Поля: олимпиада, класс, год, тур, условие, тип, тема, решение, ответ, ссылка, время сбора и оценка сложности 1–10. |
| `unavailable_ids` | ID задач, которые сайт сообщил как недоступные. |
| `problem_fts` | Поиск слов в теме, условии и решении. |
| `search_vectors` | Числовые представления темы с условием и решения для поиска похожих задач. |
| `search_skipped` | Тексты, которые не удалось включить в поиск из-за длины. Сейчас таблица пуста. |
| `search_meta` | Версия схемы поискового индекса. |

При изменении условия или решения поиск по словам обновляется сам. Числовые
представления надо обновить повторным запуском индексации. Поле сложности
добавляется скриптом разметки. Для копирования базы во время работы используйте
встроенный механизм безопасного копирования SQLite (Backup API). Поисковая
схема имеет номер версии; базовая схема таблицы `problems` автоматически не
мигрирует между версиями кода, поэтому изменения её полей требуют отдельного
шага.

## Запуск шагов

Запускайте команды из этой папки. Для установки библиотек выполните
`python3 -m pip install -r requirements.txt`. Для запросов к OpenRouter нужен
ключ в `olimpiads_data_v2/openrouter.key` или переменная `OPENROUTER_API_KEY`.

```bash
python3 -m scrape.parser_sdamgia_v2
./search/run_search_index.sh
python3 -m search.task_search --api-key-file olimpiads_data_v2/openrouter.key search \
  'закон сохранения импульса' --mode topic --subject physics -k 5
python3 -m labeling.label_difficulty --batch-size 32 --workers 8
```

Парсер скачивает данные с сайта; поиск по смыслу и Jev отправляют тексты в OpenRouter.
Поиск и разметку можно ограничить или настроить параметрами команд.
